# Демонстрация Java-продукта к предзащите 21 ноября

Основной показ — живые запросы МАИ; резерв — явно помеченная запись ответов.
Оба используют настоящий TLC и Java внутри Docker. Исходная модель автоматически
не исправляется, Java генерируется только после просмотра и принятия.

## Подготовка

Нужны зависимости из README, локальные Java/TLC и работающий Docker Linux daemon
с заранее загруженным `eclipse-temurin:17-jdk`. Runner образ не скачивает.
После запуска Docker проверьте `docker image ls eclipse-temurin`.
Ключ МАИ хранится только в backend/.env или окружении. Откройте два терминала.

Из backend/ для живого показа:

```powershell
$env:LLM_PROVIDER='mai'
$env:MAI_MODEL='qwen3.8-flash-next'
$env:MAI_GENERATOR_MODEL='qwen3.8-27b'
$env:MAI_REVIEWER_MODEL='deepseek-v4.1-flash'
$env:MODEL_CHECKER_JAVA=(Resolve-Path '.tools/java/bin/java.exe').Path
$env:MODEL_CHECKER_TLA2TOOLS_JAR=(Resolve-Path '.tools/tla2tools.jar').Path
$env:MODEL_CHECKER_TEMP_DIR=(Resolve-Path '.tools').Path
python -m uvicorn api.main:app --host 127.0.0.1 --port 8000
```

Из frontend/:

```powershell
npm run build
npm run start
```

По умолчанию frontend обращается к 127.0.0.1:8000. При другом адресе задайте
BACKEND_URL до запуска Next.js. Откройте localhost:3000. Не выводите .env,
ключи и полные HTTP-заголовки на экран выступления.

## Основной показ на 5–7 минут

1. **Дефект требований.** Нажмите «Подставить пример» и выполните анализ.
   В тексте явно задано, что Cancel сохраняет approved, Execute проверяет только
   approved, а исполнение отменённой заявки запрещено.
   На вкладке «Результат проверки» покажите PROPERTY_VIOLATED и
   Created → Approve → Cancel → Execute. В «Проверки Java» генерация запрещена.
2. **Явное уточнение.** Нажмите «Уточнить требования и проверить снова».
   Замените `не меняя approved` на `сбрасывая approved=false` и подтвердите
   новый анализ. Проверьте PROPERTY_HOLDS, тот же запрет и новый effect Cancel.
   Покажите предположения/вопросы: отсутствие предположений не доказывает полноту.
3. **Принятие.** Откройте «Проверки Java», отметьте просмотр и нажмите
   «Принять эту модель». Генерация — отдельная кнопка, автоматически не запускается.
4. **Разные свидетельства.** Нажмите «Сгенерировать и проверить Java».
   Покажите фактические роли qwen3.8-27b и deepseek-v4.1-flash,
   компиляцию PASSED и поведенческое покрытие. READY появляется только после
   всех обязательных этапов с совпадающими отпечатками.
5. **Исходники.** Перейдите в «Java-код». Выберите файл, покажите сохранение
   переменных/guards и исправленный Cancel. Код прокручивается внутри панели,
   возвращение на «Проверки Java» сохраняет принятие и отчёт. Скачайте ZIP;
   report.json связывает исходники, модель, reviewer и runner.
6. **Отрицательный код.** Покажите сохранённые результаты трёх намеренных
   ошибок из [отчёта](java-evaluation.md). Запустите интеграционный тест ложного
   approved=true: неправильная реализация остаётся JAVA_CHECK_FAILED.
   Не демонстрируйте ручное исправление кода как результат генератора.
7. **Границы.** TLC проверяет модель; LLM-рецензия и тесты Java не дают
   универсальной гарантии эквивалентности или правильной интерпретации текста.

## Резервный показ без МАИ

Остановите основной backend. В backend/ с теми же настройками Java/TLC и Docker:

```powershell
python -m uvicorn evaluation.replay_java:app --host 127.0.0.1 --port 8000
```

Frontend остаётся production-сборкой. Повторите сценарий заявки; исправление
должно явно содержать `approved=false`. Этот режим поддерживает только контрольную
заявку, не произвольные требования. API возвращает mode=recorded, во вкладке
«Проверки Java» видна надпись **РЕЖИМ ЗАПИСИ**. Модели/Java/ревью взяты из
проверенных ответов 15 ноября; TLC и javac/поведенческие тесты запускаются заново.
Это не новый живой вызов LLM, и ведущий должен прямо это сказать.

Для независимого offline-повторения реальных исходников и ложного одобрения:

```powershell
$env:JAVA_RUNNER_INTEGRATION='1'
python -m pytest -q tests/test_java_evaluation.py
```

## Отказы и очистка

- Отказ reviewer, ошибка API/JSON/timeout, недоступный Docker/JDK,
  COMPILE_ERROR и неполное покрытие не дают READY. Анализ TLC остаётся видимым.
- При редактировании требований старый кейс отзывается на сервере; поздний ответ
  предыдущей генерации не возвращает готовый модуль.
- Без явного удаления кейсы хранятся до часа, максимум 64 в одном процессе.
  DELETE `/api/v2/cases/{id}` удаляет данные; перезапуск также очищает память.
- Runner удаляет каждый `mai-java-*` контейнер и временные файлы. После показа
  проверьте `docker ps -a --filter name=mai-java-`, затем остановите оба сервера.
  Не удаляйте чужие Docker-контейнеры или образы общей очисткой.
