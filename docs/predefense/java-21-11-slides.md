# Материалы выступления к 21 ноября 2026

Исходник девяти слайдов с заметками докладчика. Результаты живой серии
актуализированы 21 ноября.

## Слайд 1 Агент-аналитик и исполняемая Java-модель

Команда it plow, практика МАИ. Требования → проверенная модель → явно принятая
модель → Java-модуль и отчёт проверки.

Заметки: исходная задача — найти логическую последовательность, которую человек
может пропустить. Новый этап добавляет исполняемую реализацию этой же модели,
не заменяя исходный детерминированный checker.

## Слайд 2 Границы ответственности

| Компонент | Что даёт |
| --- | --- |
| Аналитик LLM | Модель и предполагаемые свойства по тексту |
| SANY и TLC | Корректность TLA+ и результат свойств конечной модели |
| Генератор LLM | Java по принятой модели |
| Другая LLM | Рецензия точных исходников |
| javac и тесты | Компиляция и проверка реализации по модели |

Заметки: не называем одобрение LLM доказательством. Все этапы привязаны к одной
модели и точным исходникам, а не к похожей версии.

## Слайд 3 Контрпример исходной ошибки

Created → Approve → Approved → Cancel → Cancelled → Execute → Executed.

Cancel сохраняет approved=true. Execute требует только approved. Получено
запрещённое сочетание Executed и cancelled=true. Генерация Java заблокирована.

Заметки: показать вкладку результата и четыре состояния TLC. В коротком
неоднозначном примере Word не все guards/effects заданы; используем полный
acceptance, а не заставляем LLM выдумывать дефект.

## Слайд 4 Уточнение и принятие

Пользователь меняет Cancel: approved=false. Тот же запрет проходит TLC.
Просмотр модели и свойств → явное принятие → отдельный запрос генерации.

Заметки: показать новый effect, PROPERTY_HOLDS и две отдельные кнопки.
Редактирование требований отзывает прежнее принятие. Присланный клиентом статус
PROPERTY_HOLDS не даёт серверного допуска.

## Слайд 5 Протокол Java-машины

```text
READY
SNAPSHOT → STATE status="Created";approved=false;cancelled=false
FIRE Approve → APPLIED + STATE
FIRE Execute при ложном guard → REJECTED без изменения состояния
```

Заметки: Java реализует ту же BehavioralModel. Effects читают старое состояние
одновременно, переменные без присваивания сохраняются. Enum, boolean, integer
и весь текущий DSL поддерживаются. Произвольные библиотеки и веб-сервис не нужны.

## Слайд 7 Проверки намеренно неверного кода

Синтаксическая ошибка → COMPILE_ERROR. Удалённый guard или неверный effect →
BEHAVIOR_VIOLATED. Даже принудительное ложное approved=true не создаёт READY.

Заметки: reviewer отклонил синтаксическую ошибку и неправильный effect.
При ревью удалённого guard ответ не прошёл валидацию.
Показываем фактические результаты, не обещаем универсальной точности LLM.

## Слайд 8 Изоляция и интерфейс

Одноразовый Docker/JDK без сети, ключей и репозитория; ограничены время,
CPU, память, PID, файлы и вывод. Исходники read-only, сборка в ограниченном tmpfs.

«Проверки Java» и «Java-код» — отдельные вкладки. ZIP содержит исходники,
модель, отчёт и совпадающие отпечатки. Файлы отображаются как текст.

Заметки: показать табы, переключение файла и отчёт. Фильтр запрещённых импортов
не заменяет изоляцию. Если Docker/JDK недоступен, готовность не подтверждается.

## Слайд 9 Границы и резервный показ

Проверяется конечная модель интерпретации. Тесты Java не доказывают полную
эквивалентность произвольной программы. Нет Java-веб-сервиса, БД, авторизации
и deployment — они не входили в согласованный этап.

Резерв: сохранённые LLM-ответы, настоящий TLC и JDK. На экране **РЕЖИМ ЗАПИСИ**.

Заметки: при сбое МАИ используем воспроизводимый резерв, прямо называем его
записью. Дедлайн этапа был 14 ноября; финальная приёмка выполнена 15 ноября.
Источник цифр и ограничений: [отчёт](../java-evaluation.md).
