# Проверка соответствия кейсу и надёжности 7 ноября 2026

Этап закрывает задачи #31–34 со сроком 07.11, 20:00 МСК. Исходный Word остаётся
источником требований: константные свойства и совместимый JSON устраняют
расхождения, SANY и управляемый порог усиливают существующий checker.
Java-продукт #35–42 имеет отдельный срок 14.11 и на этом этапе не реализован.

## Что проверено

- Настоящий TLC возвращает `PROPERTY_VIOLATED` и одно начальное состояние для
  `invariant=false`, `forbidden_state=true` и составных константных нарушений.
  Истинные инварианты и недостижимые константные запреты завершаются успехом.
- `Property.id` принимается; конфликт с `name` отклоняется. Явный адаптер,
  Python `check_behavior` и `/api/v2/analyze` дают формат Word, старый API
  сохраняет прежний JSON. Все четыре типа и шесть статусов проверены.
- UI показывает выбранные свойства, причины выбора, предположения и вопросы
  из `interpretation`; старый ответ без метаданных имеет оговорку. Редактирование
  и повторная проверка не смешивают результаты. Кнопка примера вставляет полный
  ошибочный acceptance, короткий пример Word рассматривается отдельно.
- SANY реально принимает сгенерированный модуль и отклоняет синтаксическую,
  семантическую и уровневую ошибки до TLC. Проверены timeout, отсутствие
  Java/JAR/класса, ошибка запуска и неподтверждённый разбор без ложного успеха.
- Порог `TLCGet("distinct")` реально останавливает TLC при двух различных
  состояниях для invariant, reachable и deadlock_free. Повтор с порогом 100
  завершается ожидаемым результатом. При смешанных свойствах нарушение
  сохраняется даже при остановке остальных обходов. Процессы завершаются,
  каталоги очищаются; SANY/TLC и независимые свойства делят общий timeout.

Полная семантика, формат ответа и границы порога описаны в
[публичном контракте](model-checker-contract.md).

## Реальная МАИ и ручная проверка смысла

7 ноября выполнены три серии контрольных запросов `qwen3.6-35b-a3b` к API МАИ.
Использовались только синтетические учебные сценарии. Между сериями уточнялись
инструкции; это не оценка стабильности неизменного prompt и не гарантия качества
всех последующих ответов. Обычные автотесты к сети не обращаются.

В первой серии полный ошибочный acceptance дал ожидаемые модель и контрпример,
исправленный — успех. Для «всё безопасно» LLM предложила запрет любого Executed,
хотя исполнение разрешено. Ошибка была явно видна в предположениях и объяснении;
инструкция дополнена примером различия запрета исполнения и требования согласования.

Во второй серии статус ошибочного acceptance формально совпал с ожидаемым,
но LLM инвертировала `forbidden_state.expression`: TLC правильно нашёл нарушение
уже в initial, а объяснение придумало другой путь. Такая приёмка отклонена при
ручном просмотре модели/трассы. Добавлены явный пример полярности forbidden_state,
предупреждение об initial и разъяснение ожидаемого кода TLC 12.

Финальная серия началась **07.11.2026 в 17:18:32 МСК**. Ответ сервиса подтвердил
модель `qwen3.6-35b-a3b`. Сохранены модель, результат без stdout/stderr и объяснение:
[запись серии](../backend/evaluation/recorded-interpretation-qwen36.json),
[сценарии](../backend/evaluation/interpretation-scenarios.json).

| Сценарий | Результат TLC | Ручная оценка |
| --- | --- | --- |
| Полный ошибочный acceptance | `PROPERTY_VIOLATED` | Три заданных перехода; Cancel сохраняет approved, Execute проверяет только approved. Запрещённый предикат без лишнего отрицания. Трасса Created → Approved → Cancelled → Executed с Approve/Cancel/Execute. |
| Исправленный acceptance | `PROPERTY_HOLDS` | Cancel дополнен approved=false; тот же запрет, четыре различных состояния, обход завершён. Непрошеные свойства не добавлены. |
| «Всё безопасно» | `PROPERTY_VIOLATED` | Критерий исполнения с согласованием и guard Execute предположены. Вопросы явно запрашивают критерий, initial и guards. Нарушение относится к предложенной интерпретации, а не подтверждённым правилам. |
| Короткий пример Word | `PROPERTY_HOLDS` | Проверяются выбранные достижимости и запрет исполнения без согласования; initial и детали переходов отмечены предположениями, заданы вопросы. Это не воспроизводимый ошибочный acceptance. |
| Пропущенный initial ready | `PROPERTY_HOLDS` | Только reachable, initial=false помечен предположением и задан вопрос. Путь false → Prepare → true; достижимость не подменяется инвариантом. |

Проверялись guards, эффекты, выражения свойств, трассы и тексты оговорок, а не
только совпадение статусов. В неоднозначных сценариях заранее правильного
логического статуса нет: важны видимость интерпретации и возможность уточнения.
В объяснениях возможны неточности LLM: например, во второй серии для
missing_initial сказано, что при initial=true достижимость «теряет смысл», хотя
цель уже достигнута в initial. В финальной серии этого утверждения нет.
Это не меняет сохранённый результат TLC; объяснение не является доказательством.
Списки предположений тоже могут смешивать добавленные правила с явно заданными.

## Воспроизведение

Из `backend/`, с уже настроенными Java и JAR:

```powershell
$env:MODEL_CHECKER_JAVA = (Resolve-Path '.tools/java/bin/java.exe').Path
$env:MODEL_CHECKER_TLA2TOOLS_JAR = (Resolve-Path '.tools/tla2tools.jar').Path
$env:MODEL_CHECKER_TEMP_DIR = (Resolve-Path '.tools').Path
python -m pytest -q
```

Все **255 backend-тестов** проверены без пропусков, включая **65 интеграционных**
с настоящими SANY/TLC. После полного прогона 247 тестов добавленные записи
проверены отдельным набором из 24 тестов (в нём 7 новых). Дополнительно прошли
19 тестов API/провайдера, включая новую регрессию полного текста acceptance.
Frontend: **53 теста**
(11 HTTP/прокси и 42 UI), lint и production-сборка с TypeScript прошли.

Живой smoke production frontend → Next.js proxy → FastAPI → SANY/TLC прошёл
для обоих acceptance с fake-провайдером. `/health` и главная страница возвращают
200, v2 выдаёт engine=TLC и начальный шаг 0. Smoke выявил и помог исправить
распознавание полного текста с английским Cancel в fake-провайдере; тест
сравнивает оба полных текста с acceptance-fixtures. Временные серверы остановлены.

Для повторения только сохранённых реальных ответов без сети:

```powershell
python -m pytest -q tests/test_llm_evaluation.py
```

Для нового внешнего прогона с локальным ключом МАИ:

```powershell
python evaluation/run_mai.py --model qwen3.6-35b-a3b --scenarios evaluation/interpretation-scenarios.json --output ../.local/interpretation-evaluation.json
```

Новый прогон может отличаться; не обновляйте эталон без ручной проверки смысла.
Ключи, `.env`, `.local/`, Java/JAR и временные файлы в Git не включаются.

## Границы результата

Checker проверяет конечную модель интерпретации. Полнота требований,
правильность формализации LLM, production-система, прогресс/справедливость и
исполняемый Java-модуль не доказаны. Предположения — самооценка LLM, а не
автоматический семантический аудит. Изменение правил выполняет пользователь.
`TIMEOUT` и `STATE_LIMIT_REACHED` никогда не заменяются `PROPERTY_HOLDS`.
