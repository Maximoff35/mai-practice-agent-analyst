# Контракт исполняемой Java-модели

Этап #35–42 расширяет исходный кейс: TLC проверяет BehavioralModel, затем по
явно принятой модели одна LLM генерирует Java, другая делает ревью, javac и
детерминированные тесты проверяют реализацию. Ни LLM-ревью, ни тесты не являются
формальным доказательством эквивалентности произвольного Java-кода.

## Семантика

Java реализует переменные, initial, guards и effects принятой модели, а не
новую интерпретацию текста. Поддерживаются enum, boolean, ограниченный integer;
все операторы DSL: var, eq, in, and, or, not. Effects вычисляются одновременно
по старому состоянию; переменные без effects сохраняются. Неизвестное событие
или ложный guard отклоняются без изменения состояния. Любое разрешённое событие
можно выбрать при нескольких доступных; имена конечных состояний не дают
особых правил. Допустимые завершения из terminal_states относятся к свойству
deadlock_free и не создают/удаляют переходы Java. Stutter TLC не является
новым бизнес-событием.

## Автономный модуль и протокол

Артефакт — до 32 относительных .java-файлов, главный класс и инструкция.
Никаких Maven/Gradle/Spring, внешних зависимостей или команд сборки от LLM.
Строки stdout и stdin кодируются UTF-8. После EOF процесс завершается.

```text
stdout: READY
stdin:  SNAPSHOT
stdout: STATE status="Created";approved=false;cancelled=false
stdin:  FIRE Approve
stdout: APPLIED
stdout: STATE status="Approved";approved=true;cancelled=false
stdin:  FIRE Unknown
stdout: REJECTED
stdin:  SNAPSHOT
stdout: STATE status="Approved";approved=true;cancelled=false
```

STATE всегда содержит все переменные ровно один раз. Boolean — true/false,
integer — десятичное число, enum — JSON-строка (кавычки и экранирование позволяют
сохранить `;`, `=`, пробелы и другие печатные ASCII-значения DSL). Для старых
fixtures допускается некавыченный enum без разделителей. Лишний вывод,
неверный initial/эффект/отказ или выход за домен не дают успешной проверки.

## Идентичность и принятие

model_fingerprint — SHA-256 JSON принятой модели с сортировкой ключей и без
пробелов между элементами. artifact_fingerprint — SHA-256 main_class и точных
path/content файлов, отсортированных по пути. Нормализация не меняет исходники.
Любое изменение модели/кода меняет отпечаток. Сервер хранит результат TLC;
клиент передаёт только идентификатор кейса и отпечаток, а не PROPERTY_HOLDS.
Допуск требует успеха всех выбранных свойств. При изменении требований UI
отменяет старое принятие; новый анализ создаёт новый кейс.

## Этапы и статусы

ANALYZED → ACCEPTED → GENERATED → REVIEWED → READY. Это статусы продукта,
не PROPERTY_HOLDS для Java. Генерация запускается только явным действием.
Ошибки генерации, REVIEW_REJECTED, JAVA_CHECK_FAILED, PIPELINE_ERROR и
недоступность среды сохраняют исходный анализ, не создавая READY.

Ревью содержит approved, findings (INFO/WARNING/ERROR, message, file/line,
rule/transition), фактическую reviewer_model и оба отпечатка. Невалидный ответ,
отсутствующий файл, ошибка/timeout сервиса не считаются одобрением. Для реальной
приёмки генератор и reviewer используют разные подтверждённые модели МАИ.
Замечание ERROR запрещает READY даже при approved=true.

Отчёт Java содержит раздельную compilation, coverage, status, число проверок,
ошибочное событие, ограниченный вывод и оба отпечатка. PASSED возможен только
после компиляции и полного набора состояний/событий в заданном бюджете.
CHECK_LIMIT_REACHED/TIMEOUT/OUTPUT_LIMIT_REACHED не заменяются успехом.

Тестовый обход служит построению проверок соответствия реализации, не
заменяет TLC. Для каждого найденного состояния проверяется каждое событие и
отказ неизвестного события; достижение max_checks обрывает приёмку. Конечное
покрытие не проверяет произвольную скрытую историю Java-программы.

## Среда выполнения

Сгенерированный Java и javac запускаются только внутри одноразового Docker/JDK
с network=none, read-only root, non-root user, сброшенными capabilities,
no-new-privileges, ограничениями CPU/memory/PID/tmpfs и времени/вывода.
В контейнер монтируются только временные исходники read-only. Рабочий
репозиторий, .env, ключи backend и Docker socket не передаются. По завершении
удаляются контейнер со всем деревом процессов и временные исходники.
Автоматического скачивания образа и небезопасного fallback на хост нет.

При недоступности среды возвращается ENVIRONMENT_UNAVAILABLE. Локальные
инструкции и точные настройки — в [Java runner](java-runner.md).
