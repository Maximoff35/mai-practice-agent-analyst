## Отрицательные случаи

| Намеренный дефект | Реальный reviewer | javac/поведенческие тесты |
| --- | --- | --- |
| Синтаксическая ошибка | approved=false | COMPILE_ERROR |
| Удалённый guard Execute | Ошибка API, одобрения нет | BEHAVIOR_VIOLATED |
| Неправильный effect Cancel | approved=false | BEHAVIOR_VIOLATED |

Ошибка API при ревью удалённого guard сохранена как MAIAPIError; её нельзя
считать ни правильным ревью, ни одобрением. Повторного запроса для замены этой
неудачи красивым результатом не было. Отдельные интеграционные тесты намеренно
подставляют **ложное approved=true** и всё равно запускают настоящие javac/java:
все три дефекта дают JAVA_CHECK_FAILED, READY не возникает.

HTTP-mock тесты проверяют timeout генератора/reviewer, невалидный JSON,
неизвестный файл/строку/переход, одинаковую фактическую модель и ошибки API.
Java-тесты дополнительно проверяют зависание, лишний вывод, лимит проверок,
изменение состояния после REJECTED, enum с `;`/`=`, доступ к .env хоста/сети,
heap, очистку контейнеров и временных каталогов.

## Репетиция через production-интерфейс

Основной сценарий выполнен в браузере с production Next.js, FastAPI,
**реальным аналитиком МАИ**, генератором, другой LLM-reviewer и Docker/JDK:

1. Полный ошибочный текст дал PROPERTY_VIOLATED и трассу
   Created → Approve → Cancel → Execute. UI запретил генерацию.
2. Явно изменено правило Cancel на approved=false; повторный анализ дал
   PROPERTY_HOLDS для того же запрета. Исходники не исправлялись автоматически.
3. Модель просмотрена и явно принята; генератор/reviewer дали отдельные результаты,
   компиляция и 16 проверок прошли. Исходник просмотрен, ZIP скачан через UI.
4. Содержимое скачанного ZIP сверено: model.json, исходники, report.json,
   отпечатки модели/артефакта/reviewer/runner совпадают побайтно.

На этот браузерный сценарий было шесть внешних запросов: построение/объяснение
двух моделей, генерация и ревью. Вместе с контрольной серией — 15 попыток
chat/completions (14 успешных ответов, один сбой), плюс один запрос каталога моделей.

По просьбе пользователя Java перенесена во вкладки **«Проверки Java»** и
**«Java-код»** рядом с прежними вкладками. Файлы переключаются внутри панели,
код имеет собственную прокрутку; принятие и отчёт не теряются при смене вкладки.
При изменении требований серверный кейс отзывается, даже если генерация ещё идёт.

Резервный показ использует [replay_java.py](../backend/evaluation/replay_java.py):
сохранённые ответы LLM, настоящий TLC и повторные Docker/JDK-проверки.
API и UI явно маркируют **РЕЖИМ ЗАПИСИ**, новых запросов МАИ нет.
Резерв также проверен в production-браузере: принятие, повторные Java-проверки,
Java-код и возврат к сохранённому отчёту. Подпись режима видна на всех вкладках.
Инструкция и сценарий выступления — в [java-demo.md](java-demo.md).

## Границы и воспроизведение

JDK загружен с отдельного разрешения пользователя: официальный
`eclipse-temurin:17-jdk`, digest
`sha256:5465815640e10433422217335e15a523a3e57021a1f2ae0fc3849380d237979f`.
Приложение использует `--pull never`. Изоляция и ограничения описаны в
[java-runner.md](java-runner.md); контракты — [java-contract.md](java-contract.md),
[java-api.md](java-api.md).

Из backend/ с настроенными TLC и Docker:

```powershell
$env:JAVA_RUNNER_INTEGRATION='1'
python -m pytest -q
```

Обычные автотесты не обращаются в МАИ. Для повторения внешней серии с локальным
ключом и уже установленной средой:

```powershell
python evaluation/run_java_mai.py --generator qwen3.8-27b --reviewer deepseek-v4.1-flash --output ../.local/java-evaluation.json
```

TLC проверяет только выбранные свойства конечной модели. Ревью LLM может
ошибаться; конечные тесты Java не доказывают эквивалентность произвольного кода
и не охватывают всякую скрытую историю программы. Прогресс/справедливость,
production-система, Java-веб-сервис, БД, авторизация и deployment не входят в этап.
