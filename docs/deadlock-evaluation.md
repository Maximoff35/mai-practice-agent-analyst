# Проверка блокировок и уточнений — 31.10.2026

Этап со сроком **02.11.2026, 20:00 МСК** включает задачи
[#18](https://github.com/Maximoff35/mai-practice-agent-analyst/issues/18) и
[#19](https://github.com/Maximoff35/mai-practice-agent-analyst/issues/19).
PR #29 добавляет цитаты требований и явное уточнение текста; реализация #18
дополняет backend и UI проверкой блокировок. Полный
[контракт](model-checker-contract.md) фиксирует семантику.

## Реализованное поведение

- `deadlock_free` проверяет достижимые состояния без разрешённых бизнес-переходов.
  Служебное `UNCHANGED` не маскирует блокировку: TLC проверяет `ENABLED BusinessNext`.
- Допустимое завершение задаётся только явно через `terminal_states`. По именам
  Done, Cancelled и Created завершение не предполагается. Это исключение из
  проверки блокировки, а не обрезание графа переходов.
- Путь к блокировке возвращается отдельно как `deadlock_path`, с именами переходов
  и подтверждёнными ссылками. При смешанных свойствах сохраняются отдельные
  `property_results`, пути к цели и контрпримеры.
- UI показывает цитаты свойств и шагов, тип пути и предикат допустимого завершения.
  «Уточнить требования и проверить снова» открывает текст для редактирования;
  рядом остаются исходный текст предыдущего анализа и предупреждение. При новом
  запросе прежний результат очищается.

## Реальные запросы МАИ

Провайдер `mai`, модель `qwen3.6-35b-a3b`, настоящий Java/TLC. Ожидаемая семантика
зафиксирована до запросов в [четырёх сценариях](../backend/evaluation/deadlock-scenarios.json).
Смысл полученных переменных, guards, effects, свойств и путей проверен вручную.
Время включает построение модели, TLC и объяснение; это отдельный замер, а не SLA.

| Сценарий | Ожидание и фактический результат | Время |
| --- | --- | --- |
| Ready → Finish → Done, завершение не разрешено | `PROPERTY_VIOLATED`, путь Ready → Done, переход Finish; ссылки R3/R2 | 14,54 с |
| Тот же процесс, Done явно разрешён | `PROPERTY_HOLDS`, terminal_states для Done, без пути нарушения | 14,48 с |
| Ready → Done → Ready | `PROPERTY_HOLDS`; оба перехода сохранены | 16,85 с |
| CanFinish + AlwaysReady + NoDeadlock | Достижимость подтверждена, инвариант и отсутствие блокировок нарушены; три отдельных двухсостоянийных пути | 12,81 с |

Повторно выполнены четыре прежних явных сценария из
[общего набора](../backend/evaluation/scenarios.json): ошибочная заявка — нарушение
(14,15 с), исправленная — успех (23,14 с), безопасное взаимное исключение — успех
(15,96 с), ошибочное — нарушение (11,58 с). Их модели сохранили заданные правила.
Неполный сценарий «всё безопасно» дал успех только для предположенной модели;
объяснение явно назвало предположения и запросило уточнение. Такой результат
не считается подтверждением исходных требований.

Обнаруженная при первом повторном прогоне регрессия: LLM добавляла NoDeadlock
к сценарию, где запрошен только запрет исполнения отменённой заявки. После
явного ограничения «проверять только запрошенные свойства» повторные явные
сценарии дали ожидаемые модели и статусы. Также уточнена инструкция объяснения:
нарушение может остановить обход, поэтому не означает полного исследования графа;
повторное объяснение контрпримера заявки это соблюдает. Изменение prompt снижает
ошибки, но не даёт автоматической гарантии смысловой точности.

В production-интерфейсе с реальной МАИ и TLC проверены блокировка Ready → Done,
цитаты, редактирование с видимым прежним текстом и повторный успех после явного
разрешения Done. Старый путь исчезает при новом запросе. Исправленная заявка
дополнительно проверена через тот же frontend/API после уточнения prompt.

## Повторный запуск

Настройте локальный `MAI_API_KEY`, Java/TLC по [инструкции backend](../backend/README.md).
Из `backend/`:

```powershell
python evaluation/run_mai.py --model qwen3.6-35b-a3b --scenarios evaluation/deadlock-scenarios.json --output ../.local/mai-deadlock.json
python evaluation/run_mai.py --model qwen3.6-35b-a3b --output ../.local/mai-regression.json
```

Команды выполняют реальные внешние запросы. Ключи и сырые технические логи
в записи не сохраняются; `.env`, `.local/` и локальные инструменты не входят в Git.

## Границы готовности

Все четыре типа свойств работают для конечного поддерживаемого DSL.
`PROPERTY_HOLDS` относится к выбранным свойствам модели. `deadlock_free` не
доказывает прогресс, справедливость или завершение процесса: разрешённый
бизнес-самопереход не является блокировкой. Timeout и другие незавершённые
проверки не заменяются успехом.

Интерпретация требований и объяснение остаются вероятностными ответами LLM;
пользователь просматривает модель и явно уточняет текст. Автономный диалог,
автоматическая проверка смысла, арифметика DSL, управляемый лимит состояний
и проверка production-системы не реализованы. Новые сроки этих возможностей
не назначались.
