# API принятия модели и Java-артефактов

Старые `/api/analyze` и `/api/v2/analyze` сохранены. Для Java-процесса
используйте сохранённый сервером кейс, а не передавайте свой JSON с успехом TLC.
Это учебный API без авторизации, базы данных и очереди; один backend-процесс
хранит до 64 кейсов на час. Перезапуск очищает память. Секреты LLM остаются на сервере.

## Последовательность

1. `POST /api/v2/cases` с `{"requirements":"..."}` выполняет анализ и TLC.
   Ответ: case_id, model_fingerprint, analysis (прежний AnalysisResult), accepted=false.
2. Пользователь просматривает текст, модель, предположения, выбранные свойства и
   трассы. `POST /api/v2/cases/{case_id}/accept` получает
   `{"case_id":"...","model_fingerprint":"...","accepted":true}`.
   Сервер проверяет версию и сохранённые результаты всех свойств. Иной статус,
   подмена модели или accepted=false не дают допуск.
3. `POST /api/v2/cases/{case_id}/generate` явно запускает генератор, reviewer,
   компиляцию и поведенческие проверки. Ответ PipelineReport содержит отдельные
   этапы и отпечатки. Это синхронный запрос; промежуточный статус можно получить
   через `GET /api/v2/cases/{case_id}`.
4. `GET /api/v2/cases/{case_id}/download` отдаёт ZIP только сохранённого артефакта:
   sources/*.java, report.json, model.json и README.txt. Неуспешный артефакт тоже
   доступен для диагностики; статус из report.json нельзя заменять READY.
5. `DELETE /api/v2/cases/{case_id}` удаляет анализ, принятие, исходники и отчёты.
   UI вызывает его при изменении требований, новый анализ создаёт новый кейс.

Пример принятия:

```json
{"case_id":"0123456789abcdef","model_fingerprint":"sha256-сохранённой-модели","accepted":true}
```

## Повторные запросы и ошибки

Повторная генерация очищает все прежние Java-этапы до обращения к LLM. Даже если
новая попытка упала, старое READY не восстанавливается GET-запросом. Отпечатки
reviewer и runner должны совпадать с точной текущей моделью и исходниками.
PASSED без подтверждённой compilation и полного coverage недостаточен.
Одновременная генерация одного кейса запрещена. Удаление отзывает принятие
даже во время внешнего вызова: поздний ответ не создаст READY. Уже выполняющийся
вызов может завершиться в своём бюджете, но результат удалённого кейса недоступен.

404 — неизвестный/истёкший кейс; 409 — неподходящая версия/состояние, занятый
кейс или заполненное хранилище; 422/502/503 на анализе сохраняют семантику
старого API. PIPELINE_ERROR внутри отчёта обозначает незавершённый этап;
сообщение не раскрывает сырой ответ провайдера или секреты исключений.
REVIEW_REJECTED и JAVA_CHECK_FAILED содержат доступные свидетельства отказа,
исходный анализ не стирается. Невалидная среда Java видна в compile_and_check,
не становится успешной проверкой.

Идентификатор кейса — не средство авторизации. Для публичного многопользовательского
развёртывания нужны дополнительные решения; они в этот учебный этап не входят.
[Java-контракт](java-contract.md) и [изоляция runner](java-runner.md).

Ответы содержат mode=live либо mode=recorded. Последний используется только
отдельным резервным сервером `evaluation.replay_java:app`: это записанные ответы
LLM, не новые внешние запросы. TLC и Java-проверки выполняются заново.
