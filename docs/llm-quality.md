# Проверка формализации через LLM МАИ

16.10.2026 проверены пять текстовых сценариев через API МАИ и настоящий TLC.
После уточнения prompt `qwen3.6-35b-a3b` сохранила смысл четырёх явных описаний
и получила ожидаемые результаты. Неполное описание потребовало уточнений:
`PROPERTY_HOLDS` для предложенной LLM модели не подтверждает исходные требования.
Это небольшая контрольная выборка, а не оценка качества на произвольном тексте.

## Методика и воспроизводимость

До вызова LLM в [scenarios.json](../backend/evaluation/scenarios.json) записаны
исходные тексты, ожидаемые переменные, правила переходов и свойства. Имена
сущностей и оформление JSON не считаются критерием правильности интерпретации.
Для неполного сценария ожидаемый статус не задан: необходимы уточнения.

Проверка проходит цепочку `текст → API МАИ → validate_model → TLC → объяснение`.
Семантика вручную сопоставлена с ожидаемыми правилами, отдельно от статуса TLC.
Сохранены [ответы и результаты](../backend/evaluation/recorded-qwen36.json)
без ключей и технических логов. Это записи реальных ответов, а не ответы,
подставляемые в рабочий API. Обычные тесты воспроизводят их с подменой HTTP;
четыре интеграционных теста заново проверяют явные модели настоящим TLC.

Контракт взят из [официального OpenAPI](https://api-ai.mai.ru/openapi.json):
`POST /v1/chat/completions`, `x-litellm-api-key`, `stream=false`,
`response_format={"type":"json_object"}` при построении модели. Запросы
использовали `temperature=0`, `max_tokens=8192`, timeout 90 секунд на вызов.
Эти параметры не гарантируют идентичность повторных ответов.

`Approve → Cancel → Execute` для ошибки, пустой контрпример для исправления,
непустое объяснение в обоих случаях.

## Сравнение моделей и исправление prompt

| Модель API МАИ | Проверка | Наблюдение | Решение |
| --- | --- | --- | --- |
| `qwen3.6-35b-a3b` | Пять сценариев после уточнения prompt | Четыре явные модели соответствуют тексту; неполный сценарий выявляет предположения | Выбрана для текущей конфигурации по проверенной выборке |
| `deepseek-v4.1-flash` | Ошибочная заявка | `PROPERTY_VIOLATED`, нужные правила и трасса сохранены, объяснение получено; 17,71 с | Дополнительный проверенный кандидат; остальные сценарии не оценивались |
| `Qwen3.5-122B-A10B` | Ошибочная заявка | Невалидная модель отклонена до TLC; повторная диагностика выявила неверную форму `in` | Для текущего prompt не выбрана; совместимость не подтверждена |

До уточнения prompt Qwen3.6 добавляла булевым переменным лишние `min/max`.
Все четыре таких явных сценария были отклонены до запуска TLC. Добавлены
точные формы переменных и запрет дополнительных полей. Сгенерированные модели
не очищались и не исправлялись программно; после изменения инструкций выполнены
новые запросы. Тест фиксирует отклонение ответа с границами у boolean.

В первоначальном объяснении неполного сценария LLM необоснованно заявила
соответствие требованию «всё безопасно». В инструкции объяснения добавлены
обязательные оговорки о границах `PROPERTY_HOLDS`, предположениях и вопросе по
недостающим правилам. Повторный запрос явно обозначил предположения. Это
улучшение prompt, а не гарантированное автоматическое выявление неоднозначности.

## Поддерживаемые границы

- Конечные `enum`, `boolean`, ограниченные `integer`; операторы `var`, `eq`,
  `in`, `and`, `or`, `not`; эффекты `set` с литералом или другой переменной.
- Свойства `invariant` и `forbidden_state`. Арифметики, `reachable`,
  `deadlock_free` и проверки произвольной production-системы пока нет.
- До запуска TLC JSON и семантика DSL проходят строгую валидацию. Это ловит
  ошибки формата и ссылок, но не доказывает правильность перевода требований.
- Для «всё безопасно», пропущенных начальных условий или неясной отмены нужны
  вопросы: какое состояние начальное, когда разрешено исполнение, что меняет
  отмена, какое сочетание состояний запрещено. Полноценный диалог уточнений
  пока не реализован; предположенную модель нужно просмотреть и уточнить текст.
- Ошибка объяснения сохраняет исходный результат TLC с шаблонным сообщением.
  `TIMEOUT`, `STATE_LIMIT_REACHED` и `ENGINE_ERROR` не заменяются успехом.

## Повторный запуск

В `backend/.env` локально задайте ключ `MAI_API_KEY`; настройте Java/TLC по
[инструкции backend](../backend/README.md). Из `backend/`:

```powershell
python evaluation/run_mai.py --model qwen3.6-35b-a3b --output ../.local/mai-evaluation.json
```

Можно добавить `--scenario application_buggy` для одного примера. Скрипт
выполняет реальные внешние запросы и пишет локальный отчёт после каждого
сценария. Перед публикацией нового отчёта нужно заново оценить смысл модели;
совпадение статуса с ожиданием само по себе недостаточно.
